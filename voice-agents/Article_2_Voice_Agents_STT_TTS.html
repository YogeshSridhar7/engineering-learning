1 · The Mental Model

A voice agent is a real-time pipeline

The easiest way to understand a modern voice agent is to stop thinking of it as one AI system. It is usually a chain of specialised components that must cooperate in real time.

Caller
→
Audio Input
→
STT
→
LLM / Agent
→
Tools / APIs
→
Response Text
→
TTS

Core idea: STT converts speech into machine-readable text. The agent decides what the user means and what action to take. TTS converts the response back into natural speech.

STT typeHow it worksBest useMain trade-off

Domain-adapted STTOptimised for specialist vocabulary.Medical, financial, legal domains.Needs suitable domain context/data.
4 · Streaming STT

Why live agents need partial transcripts

In a live conversation, the system cannot wait until the entire call has finished. Streaming STT produces interim text while the user is still speaking.

Caller audio: "I'd like to book an appointment tomorrow afternoon." Possible streaming transcript: 0.5s → "I'd like" 0.9s → "I'd like to book" 1.4s → "I'd like to book an appointment" 2.0s → "I'd like to book an appointment tomorrow afternoon" Final transcript: "I'd like to book an appointment tomorrow afternoon."
Testing question: does the agent act too early on an unstable partial transcript, or does it wait long enough to understand the complete user intent?

8 · Two Architectures

Cascaded voice agents vs speech-to-speech systems

Cascaded architecture

Speech → STT → LLM → TTS → Speech

Easy to inspect Clear transcripts Separate vendors possible Strong debugging visibility

Good for understanding which individual layer caused a defect.

Speech-to-speech architecture

Speech → multimodal audio model → Speech

More direct Natural timing Can use acoustic cues Harder to isolate internals

Potentially better at tone, hesitation and natural interaction, but testing may require different observability.

10 · Turn Taking

Real conversation is not clean turn-by-turn text

Voice Activity Detection Detects whether the caller is speaking or silent.
End-of-turn detection Decides whether the caller has finished their thought.
Barge-in Allows the caller to interrupt the agent while TTS is speaking.
AGENT "Your appointment is currently scheduled for—" CALLER INTERRUPTS "Actually, cancel it." GOOD BEHAVIOUR 1. Stop TTS playback 2. Capture caller audio 3. Recognise new intent 4. Confirm cancellation requirement 5. Call correct tool 6. Give updated response
11 · Testing Mental Model

When something goes wrong, isolate the layer

LayerQuestionEvidenceExample defect
AudioWas the incoming signal usable?Recording, codec, packet quality.Call audio is clipped.
VAD / turn detectionDid the system detect speech boundaries correctly?Speech timestamps.Agent cuts user off after a pause.
STTWas speech transcribed correctly?Audio + transcript.“Tuesday” → “Thursday”.
Agent / LLMWas the meaning understood correctly?Transcript + model decision.Correct transcript but wrong intent.
Tool selectionDid the agent choose the right action?Tool trace.Calls cancel instead of reschedule.
Tool parametersWere values passed correctly?API request body.15:00 becomes 17:00.
BackendDid the business system succeed?API response + database state.Booking service returns 500.
Response generationDid the agent describe the result truthfully?Backend result + generated text.Agent says “booked” after API failure.
TTSWas text spoken correctly?Response text + audio.Correct date is pronounced incorrectly.
LatencyWas interaction fast enough?Per-stage timings.Four-second silence before response.

15 · Failure Scenarios

Useful edge cases for voice-agent testing

User changes their mind“Actually, not Tuesday — make it Friday.”
User interruptsCaller speaks while TTS is still playing.
Ambiguous time“Book me at three.” Agent needs AM/PM or business context.
API unavailableBooking service returns an error or timeout.
Duplicate eventRetry must not create the same booking twice.
Long silenceAgent should reprompt instead of hanging indefinitely.
Wrong transcriptAgent should confirm critical information where appropriate.
Prompt regressionA prompt change improves booking but breaks cancellations.

17 · One-Page Memory Map

If I remember only one model

HEAR — Audio, VAD and STT determine what the caller said.
UNDERSTAND — The agent/LLM identifies intent, entities and conversation context.
ACT — Tools/APIs perform the real business operation.
VERIFY — Backend response proves whether the operation succeeded.
SPEAK — TTS turns the truthful result into natural audio.
MEASURE — Latency, accuracy, task success and failures are captured end-to-end.
When a voice-agent test fails, ask in this order: Did it hear correctly? Understand correctly? Act correctly? Verify the real outcome? Speak the right result? Do all of that quickly enough?
18 · Key Discussion Points

Concepts to be comfortable explaining

  • A voice agent is usually a pipeline, not a single model.
  • Streaming STT and streaming TTS are important because natural conversation is latency-sensitive.
  • STT accuracy alone is not enough; a correct transcript can still be misunderstood by the agent.
  • A tool call is the bridge between conversation and real business action.
  • Agent speech should never claim success unless the business system confirms success.
  • Barge-in, endpointing and VAD strongly affect how natural a voice agent feels.
  • Cascaded systems are easier to diagnose because each layer is observable.
  • Speech-to-speech systems may feel more natural but can require different testing and observability strategies.
  • End-to-end quality includes accuracy, latency, reliability, security, task completion and user experience.
  • The best bug reports identify the failing layer and attach the evidence needed to reproduce it.
